# 部署与迁移

这个服务刻意写成**零第三方依赖 + 全部可配环境变量**，所以从本地搬到云服务器只需要换一种启动方式。

---

## 一、三种网络形态，先选一个

| 形态 | 手机怎么访问 | 适合 | 代价 |
| --- | --- | --- | --- |
| **A. 纯局域网**（默认） | 同一个 WiFi 下访问 `http://192.168.x.x:8787` | 先跑通、在家用 | 出门就用不了 |
| **B. Tailscale 组网**（推荐） | 装 Tailscale，用 `http://100.x.x.x:8787` | 出门也能用，最省心 | 手机和电脑各装一个 App |
| **C. 公网服务器** | 公网域名 / IP | 电脑不常开 | 要买服务器，且口令是明文传输，**必须配 HTTPS** |

**关键一点：主动消息的"送达"不依赖上面任何一种。**
Bark 走的是苹果 APNs，只要服务进程在跑、能上网，推送就能到你手机锁屏——
你人在外面、连的是 4G，照样收得到。上面三种形态只决定**你回消息时那个聊天页面怎么打开**。

---

## 二、形态 B：Tailscale（最推荐的日常方案）

1. 电脑装 Tailscale，登录，记下它的 `100.x.x.x` 地址
2. iPhone 装 Tailscale，登录同一个账号
3. 手机浏览器打开 `http://100.x.x.x:8787/?token=你的口令`
4. 添加到主屏幕

这样不需要改任何配置，也不用开端口。Tailscale 内部是加密的，口令明文传输的风险也被包在里面了。

---

## 三、形态 C：搬到云服务器

### 1. 环境变量方式启动（不需要 config.json）

```bash
DEEPSEEK_API_KEY=sk-xxxx \
BARK_KEY=你的BarkKey \
FRIEND_PORT=8787 \
FRIEND_HOST=127.0.0.1 \
FRIEND_ACCESS_TOKEN=换个好记的口令 \
node src/server.js
```

可用的环境变量：

| 变量 | 作用 |
| --- | --- |
| `DEEPSEEK_API_KEY` | 模型 key（必填） |
| `DEEPSEEK_BASE_URL` | 换 API 网关时用 |
| `FRIEND_CHAT_MODEL` | 默认 `deepseek-chat` |
| `FRIEND_TEMPERATURE` | 默认 `1.15`，越高越跳脱 |
| `BARK_KEY` / `BARK_SERVER` / `BARK_GROUP` / `BARK_SOUND` | 推送配置 |
| `FRIEND_PORT` / `FRIEND_HOST` | 监听地址 |
| `FRIEND_ACCESS_TOKEN` | 访问口令 |
| `FRIEND_PROACTIVE` | `true` / `false`，主动消息总开关 |
| `FRIEND_QUIET_START` / `FRIEND_QUIET_END` | 静默时段小时 |

> 注意：环境变量只覆盖那几个字段，其余（间隔、每日上限等）仍然读 `config.json` 的默认值。
> 想让云上也有完整配置，把本地 `config.json` 拷过去（**先删掉里面的 apiKey**，用环境变量注入）。

### 2. systemd 常驻

`/etc/systemd/system/friend.service`：

```ini
[Unit]
Description=Friend chat companion
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=youruser
WorkingDirectory=/opt/friend
ExecStart=/usr/bin/node src/server.js
Restart=always
RestartSec=5
EnvironmentFile=/etc/friend.env

[Install]
WantedBy=multi-user.target
```

`/etc/friend.env`（权限设成 `chmod 600`）：

```
DEEPSEEK_API_KEY=sk-xxxx
BARK_KEY=你的BarkKey
FRIEND_ACCESS_TOKEN=你的口令
```

```bash
sudo systemctl enable --now friend
sudo journalctl -u friend -f
```

### 3. 用 pm2（更省事）

```bash
npm i -g pm2
pm2 start src/server.js --name friend
pm2 save && pm2 startup
pm2 logs friend
```

### 4. 加一层 HTTPS（公网暴露时必做）

Caddy 是最省事的，`/etc/caddy/Caddyfile`：

```
friend.你的域名.com {
    reverse_proxy 127.0.0.1:8787
}
```

Caddy 会自动申请并续期证书。然后把服务改成只监听本机：

```
FRIEND_HOST=127.0.0.1
```

这样外面只能通过 HTTPS 进来，口令不会明文裸奔。

> SSE 长连接（`/api/events`）经过反代时，记得关掉响应缓冲。
> 代码已经发了 `X-Accel-Buffering: no` 头，Nginx 下再补一句 `proxy_buffering off;` 更稳。

## 四、数据迁移

要迁的就一个目录：`data/`。

```bash
# 从本地推到服务器（<项目目录> 换成你放这个项目的地方，比如 ~/friend）
scp -r <项目目录>/data youruser@server:/opt/friend/
scp <项目目录>/config.json youruser@server:/opt/friend/
```

- `messages.jsonl` 是纯文本，一行一条，随时可以手工看或改
- `state.json` 里存着"已读到哪、下次主动什么时候"，换了时区也不用改（都是时间戳）
- 迁完**先改 `config.json` 里的 `port` / `host`**，或者干脆用环境变量覆盖

## 六、常见问题

**Q：手机打不开页面**
- 确认和电脑同一个 WiFi
- 确认用的是终端打印的**局域网 IP**，不是 `127.0.0.1`
- Windows 防火墙可能拦了 8787 端口，放行一下：
  `New-NetFirewallRule -DisplayName "Friend" -Direction Inbound -LocalPort 8787 -Protocol TCP -Action Allow`

**Q：推送收不到**
- 先 `node src/cli.js test-bark`，看是 Bark 的问题还是服务的问题
- 检查 Bark App 有没有被 iOS 省电模式限制：设置 → Bark → 通知 → 打开「时效性通知」
- Bark 服务地址如果填的是自建服务器，确认手机能访问到那个地址
- 看 `data/push.log`，里面记了每次推送成功或失败的原因、以及当时的标题
- 服务端日志里如果出现「对方正在应用里，跳过推送」，说明它认为你还在看页面。
  正常情况下页面关掉 90 秒后就会恢复正常推送

**Q：推送标题的名字不对**
- 标题默认从人设里解析「名字叫「XX」」，改人设第一行就能改名，不用改别的地方
- 想单独指定标题（人设名字和推送名字不同），在 `config.json` 的 `bark.group` 里写死

**Q：它一直不主动找我**
- `node src/cli.js status` 看"现在能不能发"和"上次没发的原因"
- 常见原因：静默时段、今天到上限、刚聊完不久、连续没回达到上限
- 主动消息默认间隔 75–240 分钟，不是每隔几分钟就找你，这是故意的

**Q：回复太长、太像 AI**
- 改 `data/persona.md`，重点加"一次最多 2 句""不要列点""不要反问"
- 降低 `config.json` 的 `model.maxTokens`（默认 800，可以压到 200）
- 提高 `temperature`（默认 1.15，可以试 1.3）
